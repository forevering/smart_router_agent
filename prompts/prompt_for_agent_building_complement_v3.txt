核心架构重构指令：全面接入官方 MCP SDK 与云原生连接池管理
当前系统的 `HttpMCPClient` 采用了伪造的 RESTful API (`httpx.post`)，这违背了 MCP 官方标准（基于 JSON-RPC 和 SSE/Stdio），且缺乏在多 Pod (K8s) 环境下的高可用管理机制。
请严格按照以下生产级规范，对底层通信架构进行全面重构（禁止打补丁，请从底层逻辑重新实现）：
 
1. 构建真实的领域驱动 MCP Server (`mock_mcp_servers.py`)
为了彻底验证真实 MCP 协议，必须独立于 Agent 核心新建一个 Server 运行脚本。该脚本模拟 AI 团队维护的 BFF (AI 网关) 层：
 - 使用官方 SDK：必须引入官方 Python MCP SDK（如 `mcp.server.fastapi` 或 `mcp.server.sse`）。
 - 领域分组 (DDD)：实例化两个完全独立的 MCP Server 对象：
   - `Weather_Server`：包含 `get_weather` 和 `get_typhoon_warning` 工具。
   - `Travel_Server`：包含 `get_schedule` 和 `search_flight` 工具。
 - 单端口多路径挂载：使用单个 FastAPI 实例监听 `8200` 端口，将这两个 Server 挂载到不同的路径：
   - `/weather/sse` 及 `/weather/messages`
   - `/travel/sse` 及 `/travel/messages`
 - 工具注册：使用 SDK 官方的装饰器（如 `@server.tool()`）将原有的模拟函数挂载为标准 MCP 工具。
 
2. 接口隔离与 `mcp_client.py` 核心协议重构
彻底废弃原有的 `httpx` 实现，将 `HttpMCPClient` 改造为真正的官方 MCP 客户端：
 - 完善基类接口：在 `MCPClientAdapter` 中补充抽象方法 `@abstractmethod def register_server(self, server_name: str, connection_config: Dict[str, Any]): pass`，确保上层不依赖具体实现。
 - 使用官方 SSE Client：必须使用 `mcp.client.sse.sse_client` 和 `mcp.client.session.ClientSession` 来建立连接和完成 `session.initialize()` 握手。
 - 数据格式剥离 (Data Mapping)：官方 SDK 的 `list_tools()` 和 `call_tool()` 返回的是强类型对象（如 `ListToolsResult`）。在 `HttpMCPClient` 返回结果给 Agent 之前，**必须将其反序列化/剥离为原生的 Python `Dict` 格式**，严禁让特定 SDK 的类污染 LangGraph 的流转状态。

3. K8s 生产级长连接池管理 (解决负载均衡失效与雪崩)
官方 MCP 走的是长连接。为了防止在集群环境中引发连接风暴和负载不均衡，`HttpMCPClient` 必须实现以下连接池 (`_sessions` 字典) 的管理机制：
 - 懒加载 (Lazy Initialization)：`register_server` 时仅保存配置。只有在首次调用 `fetch_tools_list` 或 `execute_tool` 时，才动态建立 SSE 连接并完成握手。
 - 空闲回收 (Idle Timeout/TTL)：为每个 Session 记录 `last_active_time`。使用 `asyncio.create_task` 启动一个后台清理协程，定期（如每 60 秒）扫描连接池。若某个连接空闲超过指定阈值（如 10 分钟），必须**主动关闭连接并从池中剔除**，以便 K8s 能够重新进行负载均衡。
 - 防雪崩重试 (Jitter Retry)：在调用工具时，若检测到长连接已断开，捕获异常后必须引入随机休眠时间（如 `asyncio.sleep(random.uniform(0.1, 0.5))`）再发起重连。严禁无脑重连导致的瞬时洪峰打挂 Server。
